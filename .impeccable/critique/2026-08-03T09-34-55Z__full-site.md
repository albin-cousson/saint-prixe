## Design Specificity Verdict

**LLM assessment**: There is exactly one genuinely authored composition on this site — the Mariage pairing (overlapping circular portraits, gold "&" medallion, engagement-announcement framing) — and it's excellent, doing exactly what PRODUCT.md asks: presenting a breeding pair as a relationship, not inventory. Everything else (roster grids, Actualités, Portfolio, Contact, À propos) is the default Tailwind marketing template: centered uppercase `h2`, `grid gap-8 lg:grid-cols-3`, white cards with a hairline border, `group-hover:scale-105`. Worse, the one thing that *is* uncopyable — a dog carrying five international show titles — renders as an undifferentiated 12px middot-run, and the homepage hero copy ("Éleveur passionné de Bearded Collies") is the generic sentence any kennel site would use, with no Alsace, no pedigree-transparency claim, and (on mobile) no dog photo at all. One specific idea, executed well, surrounded by a template — and the kennel's actual credibility is the least-designed part of the page.

**Deterministic scan**: `detect.mjs --json` over `src/pages` + `src/components` returned exit code 0 and zero findings — the mechanical pattern-based rules didn't fire on anything. That is a real result, not a skipped step, but it should not be read as "the site has no problems": the detector checks for known bad patterns (generic templates, unstyled defaults), and this site's disciplined token system and sharp-corner convention legitimately don't match those patterns. The substantive issues below came from the LLM review's own contrast-ratio math and from Assessment B's HTML-structure fallback (see next), which the pattern detector has no rule for at all.

**Visual overlays**: No browser automation tool was available in this session — confirmed independently by both assessments. No live `[Human]`-tab overlay exists this run. In its place, Assessment B fetched rendered HTML via curl for six representative routes and found: `/nos-chiots` skips a heading level (h1→h3, no h2); `/a-propos` renders **four `<h1>` elements** on one page (each content section uses h1 instead of h2); `/actualites` has all 36 post thumbnails with `alt=""` (a real gap — CLAUDE.md's documented "no alt text" exception is scoped to portfolio images, not blog thumbnails); one content-bearing puppy photo on `/nos-chiots` also has `alt=""`. These converge with Assessment A's independent code-reading findings on the same pages, which is good corroboration between the two isolated assessments.

## Overall Impression

The site has a real idea and executes it once, beautifully, then runs out of design budget everywhere else. The Mariage/Chiots pairing proves the team can do specific, restrained, brand-true work — the token system (`global.css`) is honestly documented down to *why* a color measures 3:1 and when that's acceptable. But the site's actual job — moving a visitor from "browsing" to "I trust this kennel enough to inquire" — breaks at the exact last step: the one Mariage page ends in unlinked plain text, the primary CTA buttons fail contrast at 1.98:1, and the breeder's own `siteSettings` document in Sanity — the reason this rebuild exists instead of staying on Wix — is wired into zero pages. The single biggest opportunity: fix the empty/end-states of the highest-intent flow (mariage detail → contact) before anything else, because right now that flow is a proof-of-concept, not a product.

## What's Working

1. **The Mariage composition** (`MariageCard.astro`, `nos-chiots/[slug].astro`) — the only place circular photo-framing is spent, exactly per the brand rule, and it reads as an announcement rather than a listing without a word of explanation.
2. **The token system's honesty** — `global.css`'s comment on `--color-gold-text` states measured contrast and correct usage context inline, which is why body copy passes AA even though (see below) button fills don't.
3. **The homepage's empty-guard discipline** — every section is wrapped in a length/existence check, so a half-populated dataset degrades gracefully to fewer sections instead of empty headings. (The gap is that this discipline exists on exactly one page — the mariage detail page's empty state is unlinked plain text, see P0 below.)

## Priority Issues

**[P0] The highest-intent page on the site ends in a dead end**
*Why it matters*: PRODUCT.md's success metric is literally "a visitor trusting the kennel enough to inquire." `/nos-chiots/romy-maverick` — the site's only Mariage, reached via a "Découvrir la portée ›" CTA — currently renders "Aucun chiot pour le moment. Revenez bientôt ou contactez-nous…" as plain, unlinked text. There is no link, button, phone number, or email anywhere on that page, and no Contact CTA anywhere in the homepage's `<main>` at all. The copy is also factually off: "dès qu'une place se libère" implies puppies existed and sold out, when the litter hasn't been born (`litterDate` is empty).
*Fix*: Branch the empty state on the real condition (litter not yet born vs. puppies born-but-taken — different sentences), make "contactez-nous" an actual link/button, and add a persistent "Une question sur un chiot ?" contact band to the mariage detail, dog detail, and roster templates.
*Suggested command*: `/impeccable harden`

**[P0] Primary CTA buttons fail WCAG contrast — computed 1.98:1**
*Why it matters*: `#ffffff` text on `--color-gold #d9b280` measures 1.98:1 (hover state 3.09:1); WCAG AA requires 4.5:1 for this text size/weight. This is every primary button on the site — "Découvrir la portée ›", "Voir toutes nos portées ›", "Envoyer" on the contact form — i.e. every conversion action. `--color-muted-2 #9b9a96` (2.82:1 on white) is used for blog dates, availability counts, and litter dates; a puppy-availability status badge renders at 8px. This is the one category of defect that's objectively wrong rather than debatable, and it lands exactly on the buttons meant to convert.
*Fix*: Adopt the hero's already-correct pattern (ink text on gold = 5.67:1) as the standard primary button, or darken the gold fill to ~`#7a5326` if white text is kept. Raise `--color-muted-2` to ~`#767470` and stop using anything below 12px for status text.
*Suggested command*: `/impeccable audit`

**[P1] Actualités is a 40-item undifferentiated wall, and 10 of those posts duplicate existing dog pages**
*Why it matters*: This is the show-circuit audience's only surface, and PRODUCT.md requires both audiences be served equally. Ten blog slugs are identical to dog-page slugs (e.g. `anastasia-de-chester` exists as both a blog post and a dog page, with no cross-link, and the dog is called a third name, "ANNA," on its own page). Cards show only a city name and date — the fetched `excerpt` field is never rendered — so a judge scanning results sees "BOURGES," "ANGERS," "ALES" (twice, literal duplicate), with no way to tell show results from dog-presentation posts.
*Fix*: Add a `type` field to distinguish result posts from dog presentations, render `excerpt` on cards, group by year, and cross-link dog detail pages to their same-slug blog posts.
*Suggested command*: `/impeccable distill`

**[P1] The breeder's own editable content is wired into zero pages**
*Why it matters*: PRODUCT.md's Principle 4 is that Astro+Sanity exists specifically so the breeder never needs a developer to change a real-world fact. `siteSettings` (phone, email, address, social links, footer text, nav items) is queried in `queries.ts` and imported by **no page** — the phone/email are instead hardcoded in three separate files (`Footer.astro`, `contact.astro`, `inquiry-services-page.astro`). If she updates her phone number in Studio today, she'll believe it's live and be wrong.
*Fix*: Wire `siteSettings` into the layout/Header/Footer, delete the three hardcoded copies, and render other currently-inert fields (`contactPage.intro`, `chiot.description`, `chiot.lofNumber`) or remove them from the schema if truly unused.
*Suggested command*: `/impeccable harden`

**[P1] The Shih Tzu roster has a false hover affordance and 5 orphaned, unlinked detail pages**
*Why it matters*: Shih Tzu cards render with no `href` (so they're `<div>`s, not links) but keep the same `group-hover:scale-105` zoom class as linked dog cards — the photo visibly promises a click that does nothing. Meanwhile the dog detail route's `getStaticPaths` still builds pages for all five Shih Tzu, so `/nos-chiens/naf-naf` etc. exist, are indexable, and are linked from nowhere. This reads as "the site is broken," not "there's no page here."
*Fix*: Drop the hover/scale classes when a card has no `href`; then deliberately decide whether to give Shih Tzu real detail pages (and link them) or exclude them from `getStaticPaths` entirely.
*Suggested command*: `/impeccable audit`

**Sam (accessibility-dependent)**: No skip link on any page — tabs through logo + 7 nav items + 3 submenu items every time. `/a-propos` renders four `<h1>` elements, so heading-based navigation is meaningless there. Every card is one giant link, so a screen reader announces the entire Mariage card's paragraph of copy as a single link name. The puppy carousel's prev/next buttons have `aria-label`s but no `aria-live`, so pressing "next" announces nothing.

**Casey (mobile, arriving via Facebook)**: The hero's dog photo is `hidden lg:block` — the first screen on mobile (the kennel's own stated distribution channel) is a grey block with no dog. No `og:image` is set, so the Facebook link itself has no preview photo either.

## Minor Observations

- No `404.astro` — a mistyped slug gets the host default, no nav, no way home.
- `/inquiry-services-page` is unlinked from `nav.ts` and every page — either wire it into the puppy-inquiry journey or delete it.
- `formatDateFr` and the Flourish SVG are each duplicated in two files instead of imported once.
- Two blog-card implementations diverge: one always renders a placeholder box for a missing cover image, the other omits it, making the grid ragged for the 4 posts without one.
- `KELLY`'s Palmarès lists "Vice" and "Championne d'Europe" as two separate list items — a visible data artifact from migration.
- No `sitemap.xml`, `robots.txt`, or JSON-LD for a business whose customers search "élevage bearded collie alsace."
- Libre Baskerville loads via a render-blocking `@import` inside `global.css` rather than a `<link rel="preconnect">` in the layout.
- Footer reads "Lancé et sécurisé par Albin Cousson" — worth confirming with the client whether a developer credit belongs on their commercial site.
